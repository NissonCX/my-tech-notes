# MLA 原理与 RoPE 解耦

GQA 之后还能怎么省显存：低秩压缩、上投影吸收，以及它跟 RoPE 的冲突怎么解。

## 问题

GQA/MQA 把 KV 头数压到极限（1 份），上下文一长显存还是不够。MLA 为什么还能再压一个数量级？它跟 RoPE 的冲突是什么，DeepSeek 怎么解的？

## 回答

### 核心结论

1. MLA 不"减少档案本数"，而是**压缩每份档案的内容**：把 h 下投影成低维潜向量 c 存进缓存，用的时候再上投影还原 K/V。
2. "压缩再还原"在数学上**等价于一次低秩投影**（矩阵乘法结合律），所以注意力的数学形式一点没变——变的只是参数形状和缓存内容。
3. 因为结合律，**上投影可以吸收进 Q 侧**，连 K/V 都不用还原；但 **RoPE 的位置相关性挡住了这条路**，DeepSeek 用"**解耦**"（内容段 + 小维度位置段）解决。

### 1. 从 GQA 的极限出发

```text
MHA → GQA → MQA：一直在做同一件事 —— 减少【档案本数】
  32 份   8 份   1 份

MQA 的两个问题：
① 表达力损失明显（所有 Q 头共用一份索引特征）
② 就算只剩一份，它仍然是"厚"的：每个 KV 头 K 128 维 + V 128 维
```

**"少印几本"这条路走到头了。** MLA 换了个维度：**不共享，改成压缩**。

| | 压什么 | 类比 |
|---|---|---|
| GQA / MQA | **本数**（KV 头数 32→8→1） | 少印几本档案 |
| **MLA** | **每本的内容** | 每本拍成缩微胶卷 |

### 2. 低秩压缩

```text
【MHA】  K = h × W_K                直接投影，满秩
【MLA】  c = h × W_DKV              下投影：压成低维潜向量 c
         K = c × W_UK               上投影：还原成 K
         V = c × W_UV               同理（K 和 V 共用同一个 c）
```

矩阵乘法满足**结合律**，所以：

```text
K = h × W_DKV × W_UK
  = h × (W_DKV × W_UK)
  = h × W_K′                   ← W_K′ = W_DKV × W_UK
```

**"下投影再上投影"完全等价于"用一张合成矩阵投影一次"。** 所以 K 和 MHA 的 K 形式一模一样，打分当然对得上。

区别在**秩**：

```text
W_DKV : d_model × d_c         （如 4096 × 512）
W_UK  : d_c × (heads × dim)   （如 512 × 1024）
W_K′  : 4096 × 1024，但秩 ≤ 512        ← 低秩
```

- MHA 的 `W_K` 满秩，能表达任意映射
- MLA 的 `W_K′` **低秩**，表达力受限 —— 这是有意的赌注：K/V 的表示空间有冗余

> **省显存的直接原因不是"低秩"，而是"缓存里只存 c"。** 低秩只是让"c 能还原出够用的 K/V"这件事成立。

### 3. 吸收：把上投影挪到 Q 侧

```text
打分 = Q · K
     = Q · (c × W_UK)
     = (Q × W_UKᵀ) · c          ← 结合律 + (AB)ᵀ = BᵀAᵀ
     = Q′ · c                   ← Q′ = Q × W_UKᵀ
```

`W_Q` 和 `W_UKᵀ` 都是固定参数，可以**预先合并成一张矩阵**，算 Q′ 时一步到位。

**于是打分直接用 Q′ 和 c 完成——K 不用还原。** V 同理：

```text
o = w × V_all
  = w × (c_all × W_UV)
  = (w × c_all) × W_UV          ← 先算 w×c_all，最后再乘一次 W_UV
```

### 4. RoPE 挡在中间

RoPE 要求 **K 必须带着位置信息被旋转**（机制见 [[大模型推理基础]]）。而旋转是**位置相关 + 非线性**的：

```text
没有 RoPE： score = (Q × W_UKᵀ) · c            ← 吸收成立 ✅
有 RoPE ： score = Q · RoPE(c × W_UK, m)       ← 必须先还原 K 再转 ❌
```

**为什么挪不走**：吸收靠的是结合律（线性），而旋转不满足：

```text
RoPE(c × W_UK, m) ≠ (c × W_UK) 的某个线性变换
```

后果：每算一次打分，都要为**每个历史 token** 重新做"还原 + 旋转"，成本随上下文长度线性增长，把 MLA 省下的好处吐回去一部分。

### 5. 解耦：把位置拆出去

```text
K = [ K_content ; K_rope ]            ← 沿维度拼接

K_content = c × W_UK                  走 MLA 线（可压缩、可吸收、不旋转）
K_rope    = RoPE(h × W_KR, m)         单独一条路，加 RoPE，但维度很小
```

打分拆成两段相加：

```text
score = Q_content · K_content + Q_rope · K_rope
```

| | 内容部分 | 位置部分 |
|---|---|---|
| 走哪条线 | MLA 压缩线 | 普通投影 + RoPE |
| 能压缩吗 | ✅ | ❌ |
| 维度 | 大（压缩后几百维） | **很小**（几十维） |
| 缓存存什么 | **c** | **k_rope** |

**位置段小是关键**：就算它不能压缩、要单独存一份，几十维也花不了多少显存。

### 6. 三层设计收口

```text
① 低秩压缩：上下投影把 K/V 压成 c           → 缓存只存 c
② 吸收：把上投影挪到 Q 侧                    → 用时不必还原 K/V
③ 解耦 RoPE：位置段单独拆出、压到几十维      → 让 ② 在带位置编码时依然成立
```

三层叠起来，才是"**DeepSeek 为什么 cache 高效**"的完整答案。

## 常见误解

| 误解 | 纠正 |
|---|---|
| "下投影是把 K 压成 c" | 方向反了：**h → c → K**。压缩必须发生在 K 诞生之前，否则没有省的意义 |
| "上投影 × 下投影互相抵消，等于没作用" | 是**合并成一张低秩矩阵**（结合律），不是**抵消成单位矩阵**（逆运算）。4096→512 有信息损失，不可能无损还原 |
| "就是换了个计算顺序" | 不是换顺序，是**等式变形**（同一个值换写法） |
| "低秩就等于省显存" | 低秩只是让 c 能还原出够用的 K/V；**省显存靠的是"缓存只存 c"** |
| "用了 MLA 就不用管 RoPE 了" | 相反：RoPE 正是 MLA 最麻烦的地方，必须**解耦**才能同时成立 |
| "MLA 已经是主流方案" | 不是。**GQA 是当下开源模型的默认选择**（改动小、生态好）；MLA 省显存更狠，代价是 RoPE 解耦 + 推理引擎专门适配 |

## 相关问题

- **怎么选 GQA 还是 MLA？** → 看瓶颈：**卡显存就上 MLA，图省事/要生态支持就用 GQA**。面试里答这条取舍逻辑，比答"MLA 最好"得分高。
- **为什么位置段不能也压缩？** → 它要过 RoPE，旋转要求位置信息完整；而且它本来就只有几十维，压不出多少。
- **K 和 V 都来自同一个 c 吗？** → 是，同一个潜向量 c 分别上投影出 K 和 V。
- **低秩会掉多少效果？** → DeepSeek 的结论是质量基本不降（低秩假设成立）。**具体压缩维度与实测数据待核 DeepSeek-V2 论文**，不要凭记忆报数。
