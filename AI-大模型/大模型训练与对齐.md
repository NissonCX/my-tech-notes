# 大模型训练与对齐

## 问题

Base Model 为什么还不是助手？SFT、Alignment、RLHF、DPO、RLVR 和 LoRA 分别在做什么？个人能否在本地做小模型微调？

## 回答

### 核心结论

1. 预训练学习预测下一个 token；SFT 用示范回答学习助手行为；Alignment 进一步调整模型更偏好哪类回答。
2. `fine` 表示精细、小范围调整。`fine-tuning` 是从已有权重继续训练，不是从零训练。
3. LoRA 冻结原权重 `W`，只训练低秩增量 `ΔW = AB`。训练后可选择合并回 `W' = W + AB`。
4. Local 小模型 LoRA 实验可以在 Apple Silicon 上运行，但应优先选择 0.5B–3B 模型，并使用 MLX、PEFT 等训练工具。Ollama 主要面向推理，不是首选训练环境。

### 1. 训练阶段

```text
大量原始文本
→ 预训练 Pre-training
→ Base Model

指令与理想回答
→ 监督微调 SFT
→ Instruct Model

偏好或可验证奖励
→ RLHF / DPO / RLVR
→ 对齐后的模型
```

| 阶段 | 数据 | 主要获得 |
|---|---|---|
| 预训练 | 原始文本 | 语言、知识、模式和预测下一个 token 的能力 |
| SFT | 指令与理想回答 | 助手身份、指令遵循、格式与回答方式 |
| Alignment | 偏好比较或可验证奖励 | 在多个合理回答中更偏向哪一类 |

SFT 仍然是 next-token prediction。区别在于数据和数据权重：训练更集中在期望的回答上。

### 2. 全量微调更新什么

全量微调可以更新所有可训练参数：

- Embedding 表
- Attention 的 `W_Q、W_K、W_V、W_O`
- FFN 的权重
- Norm 的 `γ、β`
- 输出投影 `W_out`

训练脚本也可以冻结部分参数，只更新最后几层或其他选定模块。

### 3. Alignment

**Alignment（对齐）** 是让模型行为与人类意图、约束和期望更一致。

它通常影响：

- 是否有帮助
- 是否安全
- 是否诚实
- 是否遵循格式
- 什么时候拒绝
- 回答的简洁度和风格

Alignment 是目标类别，不是单一算法。

| 方法 | 数据 | 机制 |
|---|---|---|
| SFT | 指令与理想回答 | 模仿目标回答 |
| RLHF | 人类偏好比较 | 训练奖励模型，再优化模型策略 |
| DPO | 偏好对 | 直接优化“选中回答优于拒绝回答” |
| RLVR | 程序可验证的奖励 | 用答案检查器、测试或规则提供奖励 |

### 4. LoRA

**LoRA = Low-Rank Adaptation，低秩适配。**

来源：Hu et al., *LoRA: Low-Rank Adaptation of Large Language Models*, 2021。

原始线性层：

\[
y=xW
\]

LoRA 输出：

\[
y=xW+x\Delta W
\]

\[
\Delta W=AB
\]

符号：

| 符号 | 含义 |
|---|---|
| `W` | 原模型权重，训练时冻结 |
| `A、B` | 可训练的低秩矩阵 |
| `r` | LoRA rank，通常远小于模型宽度 |
| `AB` | 低秩权重增量 |

训练时：

```text
W 冻结
A、B 可训练
输出 = xW + xAB
```

训练后可合并：

```text
W' = W + AB
```

LoRA 可挂在：

- `q_proj`
- `k_proj`
- `v_proj`
- `o_proj`
- FFN 的线性层
- 其他输出投影层

LoRA 降低的是训练成本。它不保证植入新知识，也不等于模型产生人类式信念。

### 5. 本地实验路线

适用设备：Apple Silicon，例如 M4 / 16GB。

推荐起点：

1. 从 Hugging Face 下载 0.5B–3B 的 Causal LM。
2. 优先使用支持 Apple Silicon 的 MLX LoRA / QLoRA 工具。
3. 准备 `train.jsonl`、`valid.jsonl`、`test.jsonl`。
4. 每行使用 chat messages 或 instruction / input / output 格式。
5. 先训练小 rank 和小上下文，做一次 smoke test。
6. 用未参与训练的问题评估泛化，再决定是否增加数据和 rank。

Ollama 模型通常是 GGUF 推理权重，不适合直接作为主流训练输入。训练时应使用 Hugging Face 的原始权重。

模型越大，训练越受统一内存限制。7B–9B 量化模型在 16GB 设备上通常很紧张。先用 0.5B–3B 验证完整流程更稳。

## 常见误解

| 误解 | 纠正 |
|---|---|
| `fine` 表示“好” | 这里表示精细、小范围 |
| SFT 只能用于 Base Model | SFT 也可用于 Instruct Model 继续调整行为 |
| LoRA 修改原始 `W` | 训练时 `W` 冻结，只训练 `AB`；合并后才得到 `W + AB` |
| LoRA 能可靠植入事实信念 | LoRA 更擅长行为适配，不能保证稳定植入知识 |
| 少量样本就能形成稳定行为 | 样本太少通常只造成过拟合并缺乏泛化 |
| Ollama 模型可直接训练 | Ollama 主要用于推理；训练应使用 Hugging Face 等原始权重和训练框架 |

## 相关问题

- **LoRA 和 SFT 是什么关系？** → SFT 是训练目标，LoRA 是参数更新方式，可以组合使用。
- **LoRA 和 DPO 是什么关系？** → DPO 是偏好优化目标，LoRA 是该目标的一种低成本参数更新方式。
- **能不能让模型只回答“C 罗最好”？** → 可以让行为倾向更稳定，但不能保证形成不可动摇的信念，也不保证所有问法都生效。
