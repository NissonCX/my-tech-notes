# 数值精度与量化

fp16 / bf16 / int8 到底是什么：从"计算机怎么存一个小数"讲到"KV cache 为什么能压成 1 字节"。

## 问题

浮点数在计算机里怎么表示？为什么 `0.1 + 0.2 != 0.3`？fp16、bf16、int8 各自的取舍在哪？KV cache 量化凭什么不伤效果？

## 回答

### 核心结论

1. 浮点数的位数分两段：**指数位管范围，尾数位管精度**；fp16 = 5+10，bf16 = 8+7。
2. `0.1` 存不准**不是"转换丢了精度"**，而是**二进制有限位装不下它**——判据：最简分母是不是 2 的幂。
3. 量化的本质是**从浮点转定点**：放弃"每个数自带范围"，改用共享 scale，靠"值域窄"成立。

### 1. 浮点数的结构

```text
值 = (−1)^符号 × 1.尾数 × 2^(指数 − 偏移)
```

| 格式 | 总位 | 符号 | **指数** | **尾数** | 十进制有效位 |
|---|---:|---:|---:|---:|---:|
| **fp16** | 16 | 1 | **5** | **10** | ~3 位 |
| **bf16** | 16 | 1 | **8** | **7** | ~2 位 |
| fp32 | 32 | 1 | 8 | 23 | ~7 位 |
| fp64 | 64 | 1 | 11 | 52 | ~15 位 |

**两条核心规律**：

```text
指数位 → 决定【范围】（能表示多大、多小）
尾数位 → 决定【精度】（有效数字有几位）
```

**bf16 vs fp16 就是一次取舍**：两者都 16 位，但 bf16 把位数花在指数上（**范围等同 fp32**，防溢出），代价是尾数只剩 7 位（精度更低）。所以**训练常用 bf16、推理存权重常用 fp16**。

### 2. 手算一个完整例子：0.75 → fp16

**第 1 步：十进制小数 → 二进制小数（乘 2 取整）**

```text
0.75 × 2 = 1.5   → 取 1，剩 0.5
0.50 × 2 = 1.0   → 取 1，剩 0    ← 余数归零，结束

0.75₁₀ = 0.11₂
```

**第 2 步：写成二进制科学计数法**

```text
0.11₂  →  1.1₂ × 2^(−1)
```

**第 3 步：填进三个字段**

```text
① 符号：正 → 0
② 指数：−1 + 偏移量15 = 14 = 01110₂      ← 偏移量让指数可无符号存储
③ 尾数：丢掉隐含的整数位 1 → "1" → 补零到 10 位 = 1000000000
```

> **隐含前导 1**：规格化后整数位永远是 1，存它是浪费，所以约定不存、解码时补回。

**第 4 步：拼起来**

```text
0 | 01110 | 1000000000
```

**第 5 步：反向解码**

```text
符号 0 → 正；指数 14 − 15 = −1；尾数补回 1 → 1.1₂ = 1.5
值 = 1.5 × 2^(−1) = 0.75  ✅
```

**第 6 步：看相邻的数**

```text
0.5   → 0 | 01110 | 0000000000
0.75  → 0 | 01110 | 1000000000     ← 指数相同，尾数第 1 位变 1
1.0   → 0 | 01111 | 0000000000     ← 指数 +1
1.25  → 0 | 01111 | 0100000000
2.0   → 0 | 10000 | 0000000000
```

**指数 +1 → 值翻倍；尾数 +1 → 增加一个最小刻度。**

**精度换算**（指数 = −1 这一段，值域 0.5~1.0）：尾数 10 位 = 2^10 = 1024 个刻度，相对精度 ≈ **1/1024 ≈ 0.1%** —— 这就是"fp16 约 3 位十进制有效数字"的来历。

### 3. 加法：对齐指数 + 归一化

```text
0.75 = 1.1₂ × 2^(−1)
0.5  = 1.0₂ × 2^(−1)       ← 指数相同，不必对齐

尾数相加：1.1 + 1.0 = 10.1₂
归一化：  10.1₂ × 2^(−1) = 1.01₂ × 2^0     ← 小数点左移，指数 +1

重新编码：符号0 | 指数(0+15)=01111 | 尾数 0100000000
```

**指数不同的情况**：要先把小指数的数**右移对齐**——**被移出去的低位就此丢失**，这是浮点加法误差的经典来源。

### 4. 为什么 0.1 存不下

**判据**：

```text
把分数化成最简形式 → 分母是不是 2 的幂？
  是 → 二进制可精确表示（1/2、1/4、1/8）
  否 → 装不下，只能存最近的近似（1/10、1/5）
```

**用"乘 2 取整"看**：

```text
0.1 × 2 = 0.2 → 0
0.2 × 2 = 0.4 → 0
0.4 × 2 = 0.8 → 0
0.8 × 2 = 1.6 → 1
0.6 × 2 = 1.2 → 1
0.2 × 2 = 0.4 → 0    ← 回到第 2 步，开始循环

0.1₁₀ = 0.0001100110011001100...₂   无限循环
```

于是：`0.1 + 0.2 = 0.30000000000000004`。

> **归因要准确**：不是"十转二时丢了精度"，而是**二进制这种表示法装不下 1/10**（10 = 2×5，含非 2 的因子）。转换只是暴露了它。

### 5. 量化：fp16 → int8 的本质

```text
fp16：[符号 | 指数 | 尾数]        ← 每个数【自带】范围信息
int8：32 个数共享一把尺子(scale)   ← 每个数只记"刻了几格"
```

**q8_0 的实际格式**：

```text
每 32 个数打成一包，共 34 字节：
  ┌──────────────┬────────────────────────┐
  │ scale (fp16) │   32 个 int8（各 1 字节） │
  │    2 字节     │       32 字节           │
  └──────────────┴────────────────────────┘
  还原：value_i = scale × int8_i

平均 = 34 ÷ 32 = 1.06 字节/数  → 相对 fp16 减约 47%
（q4_0：18 ÷ 32 = 0.56 字节/数，减约 72%）
```

**本质：从「浮点」变成「定点」**——放弃"每个数自带范围"的能力，换取存储减半。

**三个成立条件**：

| # | 原因 | 说明 |
|---|---|---|
| 1 | **值域窄** | KV 通常在 ±10 这类小范围，用不到 fp16 那么大的指数范围 |
| 2 | **精度过剩** | 模型是概率模型，1% 的数值扰动不改变"更可能是哪个词" |
| 3 | **误差抵消** | 打分是点积，各维度的随机误差相加时部分抵消 |

### 6. 精度损失的三处来源

| # | 位置 | 例子 |
|---|---|---|
| ① | **表示** | `0.1` 存成 `0.10000000000000000555` |
| ② | **运算** | 加法对齐指数时右移丢位；`0.1+0.2 ≠ 0.3` |
| ③ | **累积** | 百万步训练中误差叠加 → 数值不稳（`bf16 存 + fp32 累加`的由来） |

## 常见误解

| 误解 | 纠正 |
|---|---|
| "十进制转二进制时丢了精度" | 是**二进制表示法装不下**某些十进制小数；判据：最简分母是否为 2 的幂 |
| "bf16 和 fp16 只是名字不同" | 位数分配完全不同：bf16 是 8+7（范围大、精度低），fp16 是 5+10（反之） |
| "量化只是省空间" | 它同时**改变了数值语义**：从浮点（自带范围）变成定点（共享 scale） |
| "fp16 精度只有 3 位，不够用" | 神经网络权重本来就只需要这个量级；真正的风险在**累积**（第 ③ 处） |
| "int8 就是 1 字节/数" | q8_0 实际是 **1.06 字节/数**（每 32 个数要摊 2 字节的 scale） |

## 相关问题

- **为什么训练用 bf16 而推理用 fp16？** → 训练怕**梯度溢出**（要范围），推理要**保精度**（权重值域稳定）。
- **KV 量化到 q4_0 会怎样？** → 精度开始明显下降；q8_0 通常几乎无损。
- **scale 为什么要 32 个数共享一个？** → 更细的分组精度更高但开销更大；32 是 llama.cpp 的折中。
- **这套知识和 AI Infra 七层地图的关系？** → 原理在 **② 算子层**，开关在 **④ 引擎层**（如 `OLLAMA_KV_CACHE_TYPE`）。
