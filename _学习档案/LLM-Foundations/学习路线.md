# LLM Foundations 学习路线

## 核心结论

1. 目标不是押注某一个岗位，而是建立可迁移的 **LLM 系统基础认知**：模型、推理、应用、系统四层都能理解并做出判断。
2. 共同主干做到 **L2（能解释、能估算、能判断）**；最后选择一个方向做到 **L3（能实现、实验、调优或读源码）**。
3. 不按周排课。默认用 **30–45 分钟的可恢复学习单元**推进，进度由完成证据而不是学习时长决定。

## 最终能力

学完后应能：

1. **解释**：讲清一次生成从文本到 token 的完整链路。
2. **估算**：判断模型与硬件的显存、上下文、并发、延迟和成本边界。
3. **集成**：把模型接入 API、流式服务、工具调用、RAG 和 Agent 循环。
4. **诊断**：区分模型、推理引擎、网关、网络和应用逻辑的问题。
5. **评估**：比较模型、Prompt、RAG、Agent 和推理策略，不被榜单与营销口径误导。

## 共同主干

### 1. 模型基础

**核心问题**：模型内部怎么工作，能力从哪里来。

- 分词、嵌入、位置编码、Attention、残差、FFN、Norm、完整 Transformer 层
- 采样与生成参数、上下文窗口、Decoder-only 结构
- 预训练、SFT、RLHF / RLVR 的基本分工与能力边界
- Dense / MoE、模型配置、参数量与模型卡怎么读

**L2 产出**：能画出完整推理链，解释每层机制，知道模型能力与限制来自哪里。

### 2. 推理与 Serving

**核心问题**：模型为什么慢、贵、占显存，如何估算与优化。

- Prefill / Decode、KV Cache、Prefix Cache
- GQA / MQA / MLA、量化、批处理
- 显存容量、带宽、TTFT / TPOT、吞吐与并发
- PagedAttention、continuous batching、并行、PD 分离

**L2 产出**：给定模型和硬件，能估算上下文、并发、延迟和成本边界。

### 3. 应用与 Agent

**核心问题**：模型如何连接外部世界，形成可靠应用。

- Prompt、上下文管理与 token 预算
- Structured Output、Function Calling、工具调用
- RAG 的检索、拼接、重排、引用与失败模式
- Agent 循环、状态、记忆、规划与停止条件
- 离线评测、在线反馈、质量与成本权衡

**L2 产出**：能搭出最小 RAG 或工具调用闭环，知道 Agent 为什么失败以及如何评测。

### 4. 系统、评估与成本

**核心问题**：如何把模型可靠、安全、经济地接入系统。

- API 协议、SSE / WebSocket、流式、断流与取消
- 路由、鉴权、限流、配额、计费与对账
- 可观测性、失败分类、重试、降级与安全
- 模型评测口径、Benchmark、A/B 测试、单位成本

**L2 产出**：能追踪完整请求链路，定位问题属于哪一层，并给出观测与成本方案。

## 深度边界

| 层级 | 含义 | 要求 |
|---|---|---|
| **L1 知道** | 听过、能参与讨论 | 非重点内容可停留在这里 |
| **L2 理解** | 能解释、估算、判断 | 四块共同主干全部达到 |
| **L3 能做** | 能实现、实验、调优或读源码 | 最后只选择一个方向深入 |

明确不做：

- 不从零训练完整模型。
- 不手写 CUDA kernel。
- 不系统刷 Agent 框架，只学机制和评测。
- 不把路线扩成完整的分布式系统课程。
- 不背模型版本与价格，只保留判断方法。

## 推进顺序

```text
模型基础
  ├── 推理与 Serving
  └── 应用与 Agent
          │
          ▼
系统、评估与成本
          │
          ▼
选择一个方向做 L3 项目
```

已经学过的 Dense/MoE、KV、MLA、DSA、量化、TTFT / TPOT 不重学，只做归位、账本整合和隔日复核。

## 碎片化学习单元

默认一个单元 30–45 分钟：

1. **3–5 分钟回顾**：不看笔记回答上次的核心问题。
2. **20–30 分钟学习**：只讲一个机制，按“先讲人话 → 专业名词 → 定义 → 机制”的顺序。
3. **5–10 分钟验证**：复述、计算、写代码或记录卡点。
4. **留恢复点**：写下“下次从这里继续”。

实验和项目拆成 30–45 分钟的小里程碑；无法一次完成的，不把未完成状态当成失败。

## 单元完成标准

每个模块都要留下证据：

1. **能讲**：不看书解释机制，并回答连续三层“为什么”。
2. **能算**：完成数量级正确的估算。
3. **能做**：留下代码、实验、源码分析或设计答卷。
4. **能留存**：隔天再测仍能答出；当场流畅只记为“待隔日复核”。

进度按完成的证据计算，不按周数或学习时长计算。

## 常见误解

| 误解 | 纠正 |
|---|---|
| 必须先决定做 Infra、Agent 或后端 | 先完成共同主干，后半程再选 L3 方向 |
| 概念被提到过就等于学过 | 必须能讲、能算、能做，并隔天仍记得 |
| 碎片化学习无法系统推进 | 系统靠依赖关系和完成证据，不靠连续长时间 |
| 学完 Transformer 就懂 LLM | Transformer 只是模型层，推理、应用和系统同样重要 |
| 只学原理就够了 | 还要能估算、集成和排障 |
| 必须买 GPU 才能学 | 模型基础和大量实验可在 Mac 完成，云 GPU 只用于特定实验 |

## 维护规则

1. 发现前置知识缺失时，立即暂停当前主题并补前置。
2. 一个主题讲完且复述通过后，再写笔记和日志。
3. 每次复习更新 `最近一次复习 / 下次建议`。
4. 现实变化时调整路线，不迁就旧计划。
