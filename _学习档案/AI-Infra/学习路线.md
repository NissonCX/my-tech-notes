# AI Infra 学习路线

## 核心结论

1. 目标分两层：**职业层**——入职讯飞 MaaS API 研发组后，能读懂下游推理服务、设计对的 API；**认知层**——建立 AI 推理的底层认知，新架构能看懂、宣传能判断真伪。
2. 执行原则：**先"对话够用"，后"底层认知"**。三层知识分工：**平台层精通 / 推理层深刻理解 / 引擎层能讲清"解决什么问题"**。
3. 12 周排期（每天 3–4h × 每周 5–6 天）：**推理层收口 → 平台层 → 模型结构 → 引擎层 → 容量与成本**；每阶段用「三问答辩」验收。

## 问题

之前是问题驱动学习（遇到什么问什么）。深挖有效，但会失去方向感——学了很多点、连不成线，也不知道离目标还有多远。

岗位背景：科大讯飞「词元星火 MaaS 平台研发部 API 研发组」，**Golang 开发**。已通过面试，大四毕业后入职，中间有一段 gap 可用于系统学习。

## 回答

### 1. 目标

| 层 | 目标 | 性质 |
|---|---|---|
| **职业层** | 入职后能读懂下游推理服务、能设计对的 API | 短期、可验收 |
| **认知层** | 新架构出来能看懂、AI 新闻能判断真伪、能识别营销话术 | 长期、更值钱 |

**三个具体能力：**

- **能说**——讲清一次 API 调用从 HTTP 请求进来到 token 流回客户端的完整链路，包括钱是在哪一步算出来的
- **能接**——接新模型 / 新供应商时，知道该问对方哪几个参数（上下文长度、并发限制、是否支持 prefix cache、计费口径、流式协议）
- **能判**——延迟 / 成本异常时，能判断问题在自己这层、网络层，还是下游推理层

### 3. 三层知识

**① 平台层 —— 精通**（本职工作）

| 模块 | 具体内容 |
|---|---|
| 多协议适配 | OpenAI / Responses / Anthropic 三种出参的字段映射 |
| 计量与计费 | token 口径、缓存命中价（价差可达 30 倍）、畸形数据兜底（`cache_read_input_tokens` 未命中可能是 `-1`） |
| 限流与配额 | 错误码语义 → 重试/降级策略（秒级流控可重试，日流控重试无用） |
| 模型路由 | 稳定别名映射、版本下线迁移 |
| 流式 | SSE / WebSocket 差异、断流与半包处理 |
| 可观测性 | TTFT / TPOT / 命中率 / 队列深度怎么采、怎么暴露 |

**② 推理层 —— 深刻理解**

Transformer 执行链 ✅、KV cache 与显存 ✅、prefix cache 与命中率 ✅、**MLA / MoE / 量化**（待学）、**prefill-decode 权衡与批处理**（待学）

**③ 引擎层 —— 能讲清"解决什么问题"**

PagedAttention（显存碎片）、continuous batching、FlashAttention、PD 分离与并行策略

### 5. 教材

**主教材**：李博杰《深入理解 AI Infra：量化分析与系统设计》（[GitHub](https://github.com/bojieli/ai-infra-book)｜[在线阅读](https://bojieli.github.io/ai-infra-book/)，Apache-2.0，5.7k Star，持续更新）

- 方法论：**从约束推导设计**——先算硬件允许的上限，再看实测离上限多远
- 覆盖：**推理层强**（MLA / MoE / KV 容量账本 / 前缀复用）、**引擎层强且偏定量**（PagedAttention、连续批处理都带算例）
- **缺口：平台层几乎为 0**（SSE / WebSocket / 协议适配 / 计费口径 / 可观测性均未覆盖）
- 用法：**当字典 + 算例库，不要从头读到尾**；配套 `calculations/calc.py` **不需要 GPU**

**平台层补缺**（书里没有的那一层）

- [QuantumNous/new-api](https://github.com/QuantumNous/new-api)——**Go 写的多协议 LLM 网关**（49k Star），三协议互转 + 额度计费，**本岗位模块的工业级参考实现**
- 协议原文：[OpenAI Responses 流式](https://developers.openai.com/api/docs/guides/streaming-responses)、[Claude 流式 / 限流 / Token 计数（中文）](https://platform.claude.com/docs/zh-CN/build-with-claude/streaming)、[讯飞星火推理 HTTP](https://static.xfyun.cn/doc/spark/推理服务-http.html)
- [vLLM Prometheus 指标清单](https://docs.vllm.ai/en/latest/design/metrics.html)——做 MaaS 大盘可直接抄字段

**引擎层补缺**

- [AIInfraGuide](https://caomaolufei.github.io/AIInfraGuide/)——中文，补"代码里怎么实现"（vLLM 源码专章）
- [zero-to-sglang](https://datawhalechina.github.io/zero-to-sglang/)——SGLang 官方 × Datawhale，Part II 手搓 mini 引擎、第 5 章讲 HTTP 服务与流式
- 论文最小集：PagedAttention/vLLM、Orca、FlashAttention、DeepSeek-V2（MLA）、DeepSeek-V3（MoE + PD 分离）

### 7. 验收：每阶段一次「三问答辩」

1. **讲**——不看书，用自己的话讲 5 分钟
2. **追**——连问 3 个"为什么"，第三层答不上就是没懂
3. **估**——一道粗算题，**数量级对即可**

> 第 2 步才是真筛子。实例：prefix cache 为什么是断崖？→ 为什么改中间等于改后面？→ 为什么 `h_t` 依赖前面全部？

### 8. 怎么维护这份路线

每完成一个阶段，更新上面的状态标记与「核心结论」；发现路线与现实不符（比如入职后工作内容不同），**以现实为准改路线**，不要迁就计划。

## 常见误解

| 误解 | 纠正 |
|---|---|
| "学完 Transformer 就等于懂推理了" | Transformer 只是地基；难点在推理服务与引擎层 |
| "先把数学补完再学工程" | 工程向**按需补数学**：够算账、够读论文即可 |
| "学得越多越好" | 有产出（笔记 + 算例 + 实验）才算学过 |
| "面试官问得简单，就不用学那么深" | 岗位要求不等于个人标准；gap 是唯一有大块连续时间的窗口 |
| "必须买 N 卡才能学" | 只有引擎层实验需要；算例、7B-Q4、Go 网关用现有 Mac 都够 |
| "平台层有现成教材" | **没有**——该层无中文系统教材、无权威计费规范，只能靠协议原文 + 开源网关源码 |

## 相关问题

- **为什么先平台层而不是先钻底层？** → offer 已到手，面试紧迫性消失；平台层知识独立、能立刻产出作品，且入职先用。
- **Lite/Pro/Max 这些模型版本怎么记？** → 不用记，记"要暴露稳定别名、内部做路由"这条设计原则即可。
- **训练要不要学？** → 不碰。MaaS 是推理侧；只需知道预训练 / SFT / RLHF 分别干什么。
- **硬件什么时候配？** → 不急。现有 Mac 覆盖阶段 1–2 的全部实验；阶段 4 的 CUDA 实验租云卡即可。真要配时看 [[本地大模型推理主机选型]]。
