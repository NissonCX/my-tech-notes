# my-tech-notes

技术学习笔记。**按领域分文件夹**（一层，不嵌套），跨领域关联靠 frontmatter 标签与双链，导航靠这一页。

## 怎么用这个仓库

**两句话原则**：

```text
① 日常：学到的东西直接记进【对应的领域目录】（AI-大模型/、后端与语言/…）
② 定期：整理出【学习档案】放进 _学习档案/（学习路线、复习清单、知识地图）
```

**但「学习日志」走日常节奏**——每次会话结束追加一条，因为"我当时是怎么想错的"隔几天就记不清了。

| 文档 | 频率 | 什么时候写 | 打开它的理由 |
|---|---|---|---|
| **领域笔记** | 每次学到新东西 | 一个主题讲完 + 复述通过 | 查某个知识的细节 |
| **学习日志** | **每次会话结束**（轻，5 分钟） | 追加：学了什么 / 产出 / **我犯过的错** | **复习时第一个打开**——那是只属于你的薄弱点 |
| **复习清单** | 一个阶段结束（重） | 掌握条目有增减时 | 想知道"我到底掌握了多少" |
| **学习路线** | 开新方向时 + 阶段推进 | 阶段状态变化 | 想知道"学到哪了、下一步是什么" |
| **知识地图** | 出现新知识模块时 | 加节点 + 连线 | **一屏看全局** |

> 一句话：**知识进领域目录，过程进学习档案；日志每次都记，计划定期整理。**
> 完整流程（讲授规范、复述闸门、四类文件格式、从零重建）在全局 skill **`study`** 里。

## 为什么从「平铺」改成「按领域分文件夹」

这是一个**有记录的决策反转**，两次的理由都写下来，方便以后复盘。

**原来平铺（2026-10-01 ~ 10-03）的理由：**

| 问题 | 说明 |
|---|---|
| 文件夹是单标签 | 一篇笔记只能放一个地方，而《HTTP 框架本质：Gin 与 Kitex》既是 Go 又是架构设计 |
| 分类维度会打架 | 原来的 `Others/` 里塞着 Git、正则、网络代理、LazyVim、代码规范——唯一共同点是"不是 Java 也不是 Go" |
| 会持续膨胀 | 以后学 Rust、K8s、AI Infra…… 每加一个就要开文件夹并纠结归属 |
| 和 Obsidian 重复 | Obsidian 原生的分类工具是标签、搜索、图谱、双链 |

**改成文件夹的原因（2026-10-03）：**

1. **实际使用场景是打开 Obsidian 看文件列表**——单层平铺 24 篇时，领域之间**没有任何视觉分界**，而且以后要学的领域只会更多。
2. 原论证的真正靶子是「**分类维度打架**」，而解法不是"干脆不分"，是「**文件夹管粗归属、标签管跨领域**」——这两者本来就不冲突。
3. `Others/` 那种失败模式，根源是**把文件夹当精细分类用**（一篇笔记纠结放哪）。新规则里文件夹只回答"**它最主要属于哪一块**"，一个大致判断，不追求精确。

**四条现在生效的规则：**

| 工具 | 负责什么 |
|---|---|
| **文件夹** | 笔记的**主领域**，一层，不嵌套 |
| **标签** | 跨领域属性（`tags: [大模型, AI-Infra]`） |
| **双链** | 知识点之间的关联（`[[笔记名]]`） |
| **本页索引** | 人工维护的导航 |

> 新增领域就开新文件夹——**这是正常的，不是膨胀**。
> 而且 Obsidian 的 `[[双链]]` 按**文件名**解析，**移动文件不会断链，分类可以随时调整**。

### Backend Engineering

- 产品定位：多公司设备维修平台，首版只启用一个种子租户。
- 工程基线：遵循《阿里巴巴 Java 开发手册（黄山版）》；【强制】作为硬门槛，【推荐】默认采用并记录偏离。
- ID 方向：数据库关系使用 `BIGINT UNSIGNED`，公开 UUID 使用 `CHAR(36)`。
- 首版范围：登录授权、工单主流程、状态机、并发控制、审计、MySQL、CI/CD。
- 明确不做：RabbitMQ、首发 Kafka/ES、库存和在线支付。
- v2 触发器：出现可靠异步副作用后，使用 MySQL Outbox + Kafka。

完整阶段和技术触发条件见 [[_学习档案/Backend-Engineering/学习路线|Backend Engineering 学习路线]]。

## 笔记格式

元信息写在 frontmatter（Obsidian 属性能识别；正文里写"标签：xxx"识别不了）：

```markdown
---
date: YYYY-MM-DD
tags: [标签1, 标签2]
---

# 标题

## 问题
## 回答
### 核心结论
### …
## 常见误解
## 相关问题
## 技术拓展
```

**复习时只看两处**：开头的「核心结论」和末尾的「常见误解」。

标签不能含空格，多个词用连字符：`KV-Cache`、`AI-Infra`。

详细规则见 [AGENTS.md](AGENTS.md) / [CLAUDE.md](CLAUDE.md)。
